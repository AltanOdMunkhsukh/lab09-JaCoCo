**Тайлангийн ажиглалт.** Улаан ромботой мөрүүд (25, 26, 54) нь хэзээ ч хүрээгүй мөрүүд бөгөөд 95, 85 оноо эрт буцдаг тул `letterGrade`-ийн сүүлийн шалгалтууд болон `scholarship`-ийн сүүлийн `if` ажиллаагүй. Шар ромботой мөрүүд (20, 24, 31, 36, 48, 51, 52, 53) нь нөхцөлийн зөвхөн нэг үр дүнг (ихэнхдээ "худал" эсвэл "үнэн" аль нэгийг) туршсан салаанууд юм. Огт хүрээгүй улаан мөрүүд (21, 27, 32, 39, 40, 49, 55) нь `IllegalArgumentException` шидэх алдааны замууд, `switch`-ийн C ба D тохиолдол, мөн сүүлийн `return`-ууд байв. Шалтгаан нь нэг: эхний 5 тест зөвхөн хүчинтэй оролтоор эрт буцдаг замыг л туршсан.

## Хэсэг B: CFG ба 100% branch хамралт

`scholarship()` функцийн CFG-г `cfg.png`-д зурсан: 9 шийдвэр (N1–N9), нийт 18 ирмэг (JaCoCo нөхцөл бүрийг тусдаа салаа гэж тоолдог тул `||` ба `&&`-ийн нөхцөл бүр тусдаа зангилаа). Ирмэг бүрийн хажууд түүнийг дайрдаг тестийн нэрийг бичсэн.

Хамрагдаагүй ирмэгүүдийг хаахын тулд A-гийн 5 тест дээр **16 тест нэмсэн** (`letterGrade` 5, `gpa` 3, `scholarship` 8), нийт **21 тест** шаардагдсан (`results/mvn-verify-B.txt`: `Tests run: 21, Failures: 0`). `results/jacoco-B.csv`-д **BRANCH_MISSED = 0, LINE_MISSED = 0** (Branch 41/41, Line 25/25). Exception-ы замуудыг `assertThrows`-оор шалгасан; `gpa < 0 || gpa > 4 || credits < 0` нөхцөл бүрт тусдаа тест бичсэн.

## Хэсэг C: Давталтын заагийн тестүүд

`gpa()` доторх давталтад 0 / 1 / 2+ дүрмийг хэрэгжүүлсэн:

| Давталт | Тест |
|---|---|
| 0 удаа | `gpa_empty_throws` (хоосон массив), `gpa_null_throws` (null) — `assertThrows` |
| 1 удаа | `gpa_oneScore_returnsThatGrade` — `gpa([95]) == 4.0` |
| 2+ удаа | `gpa_manyScores_returnsAverage` — `gpa([95, 85, 75, 65]) == 2.5` |

**Хамралт өсгөдөггүй ч яагаад хэрэгтэй вэ.** Эдгээр тест хамралтыг нэмээгүй, учир нь мөр, салаа бүр өмнө нь хамрагдсан байсан. Харин хоосон массив, нэг элемент, олон элемент гэсэн заагийн тохиолдлуудад давталтын төлөв (нийлбэр, хуваагч) өөр өөр ажилладаг тул `i < length - 1` гэх мэт нэгээр андуурсан алдаа эсвэл тэгд хуваах алдааг зөвхөн эдгээр тест л барина.

## Хэсэг D: Хамралт 100% — гэхдээ алдаа амьд

Branch хамралт 100% байхад спецификацийн зааг утгуудыг шалгах `letterGrade_boundaries` параметртэй тест нэмсэн (0, 59.99, 60, 69.99, 89.99, 90, 100). Үр дүн (`results/mvn-test-D-fail.txt`): `Tests run: 30, Failures: 1`, унасан тест `letterGrade_boundaries[3]` (оноо 60):

~~~
expected: <D> but was: <F>
~~~

Шалтгаан нь `ScholarshipCalculator.letterGrade` доторх `if (score > 60) return "D";` — спецификаци 60-69.99-ийг "D" гэдэг тул 60 мөн D байх ёстой, харин код 60-ыг хассан. Засвар: `score > 60` → `score >= 60` (commit: "Fix letterGrade: > 60 to >= 60, spec says 60 is D"). Эцсийн байдал: `results/mvn-verify-final.txt` — `Tests run: 30, Failures: 0`, `BUILD SUCCESS`; `results/jacoco-final.csv` — **BRANCH_MISSED = 0, LINE_MISSED = 0**.

## Дүгнэлт

`score > 60` ба `score >= 60` хоёр ижил салаануудыг үүсгэдэг: 65 оноо "D" руу, 50 оноо "F" руу орох тул хоёр тестээр ирмэг бүр дайрагдаж branch хамралт 100% болсон ч алдаа илрээгүй. Зөвхөн яг 60 гэсэн заагийн утга л хоёр нөхцөлийг ялгадаг. Хамралт нь кодын аль хэсэг ажилласныг хэмждэг боловч ажилласан үр дүн спецификацитай таарч байгааг, assertion зөв эсэхийг, эсвэл дутуу бичигдсэн функцийг хэмждэггүй. Тиймээс хамралт нь тестийн цоорхойг олоход зайлшгүй хэрэгтэй хэрэгсэл ч, тест хангалттай гэдгийн нотолгоо биш бөгөөд зааг утгын тест зэрэг спецификацид суурилсан тестээр нөхөх ёстой. Мөн хамралтын тоо өөрөө зорилго болбол (Goodhart-ын хууль) тестийн чанарыг буруу харуулж болохыг энэ лабораторид нүдээр харсан.
